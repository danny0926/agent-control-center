# 公開控制台設計指引

本文件描述 Agent Control Center 的公開資訊與互動原則。所有案例均為完全合成，不來自真實個人、組織、repo、工作階段或內部產品計畫。需求以 [PRD](PRD.md)、[前端規格](FRONTEND_SPEC.md) 與 [API 契約](API_CONTRACT.md) 為準。

## 設計目的

讓使用者迅速知道目前的產品結果、可相信的證據、需要自己的決定及下一步。先呈現一般人可理解的狀態，再展開工作識別、技術操作與原始證據。工具活動量、token 消耗或 Agent 忙碌不表示產品完成。

## 資訊架構

- 所有專案：每個專案獨立的狀態、待處理事項與資料新鮮度。
- 計畫：Goal、Milestone、Epic 與工作成果的可折疊階層。
- 決策：需要人回答的具體問題、證據、建議、範圍與影響。
- Agent：精確工作階段、來源限制、目前目標與受權限控制的操作。
- 驗收：逐條 acceptance、必要檢查、版本、證據及失效原因。
- 通知：狀態轉換的持久紀錄，返回正確專案與工作。

最上層保持產品語言；terminal、schema 與 Git 識別放入詳情。跨專案資訊不可合成模糊的總完成百分比。

## 完全合成的使用案例

「示例任務板」是一個測試用產品。M0 的成果是使用者可登入；M1 是任務匯入前可預覽；M2 是失敗時有清楚說明與重試方法。

某項匯入工作的狀態可顯示「程式已更新，瀏覽器驗收尚未核對」。展開後才呈現必要條件、Git revision 與合成測試報告。另一項可顯示「需要你決定是否允許分享測試摘要」，不貼入真實 prompt 或帳號資訊。

這些名稱與階段只用來示範 UI，不能顯示成即時 runtime、真實客戶需求或已驗證產品進度。預覽畫面固定標示「合成示例」。

## 桌面與手機

桌面保留專案導覽、內容與可關閉的詳情區。小螢幕把深層內容改成單欄，不壓縮成無法閱讀的表格。以 1440px、1024px、390px 檢查找通知、找決策與逐條驗收流程；實際支援範圍以測試證據為準。

操作保持可見的焦點、完整 label 與錯誤關聯。狀態同時有文字和圖示，不能只靠紅綠色。對話或 drawer 關閉後返回原始焦點；通知不搶走正在輸入的焦點。

## 狀態與證據

- working 表示 runtime 有工作觀測，不表示已通過驗收。
- Agent 本輪結束與 Agent 回報 goal 完成分開。
- owner_attested 表示擁有者逐條確認；不冒充服務自動執行測試。
- unknown、stale、partial、failed 與 unrun 保留不同意思。
- 驗收證據失效後保留原紀錄，顯示原因與重新核對入口。

## 操作權限

開始 Agent、傳訊與 shell 都可能有副作用。使用者應先看見動作、專案、精確目標與權限狀態。按鈕顯示只能提供說明，後端必須獨立驗證。危險指令確認不能取代授權；加入組織不能自動取得別人的電腦控制權。

## 通知與隱私

預設桌面通知只顯示一般摘要，詳情留在重新驗證權限後的控制台。支援關閉提醒、事件及專案篩選、安靜時段。歷史載入不彈出大量提醒；不承諾未支援的關頁推播。

公開畫面、截圖與測試採合成資料；不使用真實個人路徑、帳號、session UUID、內部專案名稱或日誌。品牌使用系統字體及通用狀態語言，不從私有產品複製領域文案或設計識別。
